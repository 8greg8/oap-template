## What was done

- Rewrote `.husky/pre-push`. It sources `scripts/config/gate.sh` for `MAIN_BRANCH` and
  `DEVELOP_BRANCH`, reads stdin once, and makes two passes over the pushed refs.
  - Pass 1 is the existing `.agents/`-only decision, unchanged in behavior. It still breaks early,
    which is safe because it only decides whether the whole push is skipped.
  - Pass 2 runs for every pushed ref and calls `python3 scripts/changelog.py check <base> <local_sha>`.
    The branch comes from `remote_ref`. `main` and `develop` use `<remote_sha>..<local_sha>`, and a
    first push of either (all-zero `remote_sha`) is not checked. `hotfix/*` uses the merge base with
    `origin/main`. Every other `refs/heads/*` branch uses the merge base with `origin/develop`.
    Tags, deleted refs and other non-branch refs are skipped.
  - A failing `git merge-base` or a missing origin ref skips the check for that ref with a stderr
    note. `changelog.py` exit 2 does the same. Exit 1 marks the push failed. The hook rejects the
    push after all refs are checked and before the gate starts. Otherwise it runs the gate.
- Added the same branch check to `scripts/gitflow.sh finish`, after the worktree check and before
  the gate and the merge. The base is `origin/$base` when `refs/remotes/origin/$base` exists, else
  the local `$base`. The tip is `refs/heads/$branch`. A failure stops with a message naming the
  fragment path.
- Tests. `tests/test_hooks.py` gained 20 collected cases in a "changelog fragment check" section, and
  `_run_pre_push` now copies `changelog.py`, `next_version.py` and `config/gate.sh` into the
  fixture. `tests/test_gitflow.py` gained four cases and copies `changelog.py` and
  `next_version.py`. The two existing end-to-end tests (`fix` kind and `feature`) now add a
  fragment. `_commit` in the hook tests takes an optional message.
- Added `changelog.d/T-0023.changed.md`, which describes the rule as breaking.

## Known limitations

- The acceptance command names `origin/develop`, which assumes a pushed branch. It was run with
  local `develop` (`cb84a65`, the branch point). The orchestrator should rerun it with
  `origin/develop` after pushing.
- The executor ran the hook only under `sh -e` through the test fixtures, as the existing hook tests
  do. The independent verifier then ran it under real `git push` against local bare remotes.
- Other non-branch refs (for example `refs/notes/*`) are skipped, as are tags. The plan lists only
  tags and deleted refs, so this is the conservative reading of "any other branch".
- `changelog.py` exit codes other than 0 and 2 (for example 127 when `python3` is missing) block
  the push. Only exit 2 skips the check.

## Lessons learned

- The `scratch` fixture in `tests/test_gitflow.py` runs `gitflow.sh start`, which fetches and
  recreates `refs/remotes/origin/develop`. A test that needs that ref absent must delete it after
  `start`, not before.
- A new remote branch (all-zero `remote_sha`) never takes the `.agents/`-only skip, so a test of
  that skip must push with a real `remote_sha`.
- Remote-tracking refs for hook tests can be made with `git update-ref refs/remotes/origin/<name>
  <sha>`, with no remote configured.
