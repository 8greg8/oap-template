### Reproduction of the push behavior

Script run with git 2.43.0. `push.default` is unset, so git uses `simple`. A bare repo `origin.git` has a `develop` branch; `work` is a clone of it.

Command as currently written in `CONTRIBUTING.md`:

```
$ git worktree add ../wt-default -b docs/T-9999-x origin/develop
Preparing worktree (new branch 'docs/T-9999-x')
branch 'docs/T-9999-x' set up to track 'origin/develop'.
HEAD is now at 266d7a6 init
$ git status -sb
## docs/T-9999-x...origin/develop
$ git config --get branch.docs/T-9999-x.merge
refs/heads/develop
$ git push
fatal: The upstream branch of your current branch does not match
the name of your current branch.  To push to the upstream branch
on the remote, use

    git push origin HEAD:develop

To push to the branch of the same name on the remote, use

    git push origin HEAD
[exit=128]
$ git push -u origin docs/T-9999-x
 * [new branch]      docs/T-9999-x -> docs/T-9999-x
branch 'docs/T-9999-x' set up to track 'origin/docs/T-9999-x'.
[exit=0]
```

With `--no-track`:

```
$ git worktree add ../wt-notrack --no-track -b docs/T-9998-y origin/develop
Preparing worktree (new branch 'docs/T-9998-y')
HEAD is now at 266d7a6 init
$ git status -sb
## docs/T-9998-y
$ git config --get branch.docs/T-9998-y.merge
(no upstream configured)
$ git push
fatal: The current branch docs/T-9998-y has no upstream branch.
To push the current branch and set the remote as upstream, use

    git push --set-upstream origin docs/T-9998-y
[exit=128]
$ git push -u origin docs/T-9998-y
 * [new branch]      docs/T-9998-y -> docs/T-9998-y
branch 'docs/T-9998-y' set up to track 'origin/docs/T-9998-y'.
[exit=0]
```

Conclusion: the problem is real. Branching from `origin/develop` makes the branch track `develop`, and a first bare `git push` refuses. `--no-track` removes the wrong upstream, but a first bare `git push` still refuses (no upstream). In both cases `git push -u origin <branch>` works, and a bare `git push` works afterward. The docs therefore carry both: `--no-track` (no misleading upstream) and a first push with `-u`.

## Lessons learned

- `git worktree add -b <branch> origin/develop` sets the new branch to track `origin/develop`. A bare `git push` then fails under `push.default=simple` because the names differ. `--no-track` leaves no upstream, so the first push still needs `git push -u origin <branch>`.
- Line numbers quoted in a task's context can drift as other tasks merge. The `AGENTS.md` citations had moved by two lines.
