# Report — T-0012: Make staged-file handling NUL-safe in gate and autofix scripts

## Summary

`gate.sh --staged` and `autofix.sh --staged` now pass staged files named with a double quote, a non-ASCII character or a newline to every command as one intact argument. All acceptance criteria are met except the bash 3.2 container run, which is `not run` because no Docker daemon is reachable. Two of the five required names (`sp ace.py`, `it's.py`) already worked before the change, so their tests are regression guards, not failing-first tests.

## What was done

1. Re-checked the context against the current files. It matched: `staged_files` had no `-z`, and both scripts read it with `read -r`.
2. Wrote `tests/test_staged_files.py` first and ran it against the unchanged scripts. 8 tests failed and 6 passed.

4. `scripts/gate.sh` and `scripts/autofix.sh` read it with `while IFS= read -r -d '' f`. The `${files[@]+...}` empty-array guard is unchanged.
5. Re-ran the new tests and the full gate.

## Lessons learned

- `git diff --cached --name-only` without `-z` C-quotes only names with a double quote, backslash, control character or non-ASCII byte. Spaces and single quotes pass through, so a test with only those names proves nothing about quoting.
