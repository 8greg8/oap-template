## Known limitations

Differences between the plan and the merged code. The docs follow the code.

1. `pre-push` also skips the fragment check, with a message, when the merge base cannot be found
   because the `origin` ref is missing. The plan names only an unlistable range.
2. `pre-push` rejects the push on any check exit code other than 0 and 2, so a missing `python3`
   fails closed. The plan is silent. `gitflow.sh finish` stops on every failure, including exit 2,
   so it is stricter than the hook.
3. `changelog.py preview` takes an optional version (the plan has none) and exits 0 with a note when
   there are no fragments. `assemble` also refuses an existing version section and no fragments.
   `check` validates every entry in `changelog.d/` at the tip, so a badly named file fails.
4. `release.py` refuses more than the plan lists: a start branch other than `main` or `develop`, a
   failed fetch, a missing local branch or `origin` ref, an existing tag, no fragments, and an
   invalid fragment. `--push` implies `--yes`. A non-canonical `--version` is a usage error with
   exit 2. `--version` does not bypass "nothing to release".
5. `--version` is compared with the highest `vX.Y.Z` tag on any branch, while `next_version.py` uses
   the last tag reachable from `HEAD`. `release.py` rejects leading zeros in a version;
   `next_version.py`'s tag pattern does not. Both are harmless in normal use.
6. `release.py` skips the merge of `develop` because it started on `main`, not because it detects a
   hotfix. Run on `main` with unreleased `develop` commits, it would release only what `main`
   holds. The docs tell the reader to run it on `main` only after a pushed hotfix.
7. The undo list `release.py` prints can contain `git reset --hard` and `git branch -f`. The docs
   say an agent hands it to the human, per the "Ask first" list.
8. `DEV_TOOLING_SPEC.md` previously described a `--dry-run` flag of `next_version.py` that the code
   never had. The rewrite drops it and documents `--quiet`.

Not covered: no GitHub Release workflow (plan D7), and no run of `release.py` against a real
