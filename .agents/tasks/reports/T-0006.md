## Known limitations

- The gate lint failure in the container is pre-existing: the `.agents/tasks/scripts/*.py` files
  have a shebang and are committed as mode 100644. It passed on the host worktree, so it depends
  on how the checkout sets file modes. Not fixed here (outside `touches`).
- Failing-dotfiles behaviour is by inspection of the subshell logic only.
- The blind container was not asked to run tests (by design it cannot).
- `uv` is not on `PATH` for the container's later shells unless the installer's profile edit is
  picked up; not checked.
- `UV_PYTHON_PREFERENCE=only-managed` needs network access on first boot to fetch CPython.

## Lessons learned

- The `mcr.microsoft.com/devcontainers/base:ubuntu` image (Ubuntu 26.04) has only
  `python3-minimal`; `uv` selects it and builds fail on missing `tomllib`. Set
  `UV_PYTHON_PREFERENCE=only-managed`.
- A git worktree's `.git` file points to a host path, so git does not work in a container opened
  on a worktree; test devcontainers from a normal clone.
- `devcontainer up --experimental-lockfile` writes the lock file next to the config used, so run
  it once per configuration.
