# Report — T-0035: Report leftover worktrees and record the gate in the verify line

## Summary

`housekeep.py worktrees` now also reports worktrees and local branches of `done` or `abandoned`
tasks, merged or not, including branches with no worktree. `report.py validate` accepts the verify
line `passed (commit <hash>; gate <record-key>; <counts>)` and still accepts the old form. The
template documents it. All acceptance criteria are met; the independent verify is recorded in the
verify line.

## What was done

- Re-checked the cited lines against `develop` (`170f4f1`): `check_worktrees()` is at
  `housekeep.py:396` and `VERIFY_LINE_RE`/`VERIFY_COMMIT_RE` are at `report.py:65-71`. No
  discrepancy with the plan.
- `housekeep.py`: `check_worktrees()` now loads the tasks, and also flags
  - a secondary worktree on the branch of a `done` or `abandoned` task, merged or not;
  - a local branch of such a task with no secondary worktree (`BRANCH ...` finding, merged or not).
  A worktree that is both merged and on a finished task's branch is one finding (the old
  "never removed" text plus the task note). Task branches are matched by task ID from the branch
  name. Branches of tasks that are not finished are ignored as before. Nothing is removed.
- `report.py`: `_verify_gate_problems()` checks the optional `gate <record-key>` part of a passed
  verify line. A part that is `gate` alone or starts with `gate ` must be `gate` plus 7 to 64 hex
  digits. A line without a gate part validates as before, so old reports are unaffected.
- `templates/report.md`: documents the new form and that the gate part is optional for old reports.
- Tests in `tests/test_report_scripts.py`; the `hk_repo` fixture now patches `load_tasks` to return
  no tasks, because the scratch repo has none and the real task files would otherwise leak in.
- `changelog.d/T-0035.added.md`.

## Known limitations

- The record-key format is not fixed anywhere yet: T-0033 (not merged) says only "key = hash". I
  accept 7 to 64 hex digits, which covers a git or SHA-256 hex digest. If T-0033 picks another
  format, the pattern `VERIFY_GATE_RE` in `report.py` needs a change.
- The gate part is optional, so a new report can omit it and still validate. The plan only asks
  that `validate` accept the form and keep the old one valid.
- A finished task's branch checked out in the primary checkout is reported as a `BRANCH` finding.
- The check reads local branches only. Remote branches are not reported.

## Lessons learned

- A scratch-repo test for `housekeep.py` must patch `load_tasks`; otherwise the real repository's
  task files decide the result, and a branch named `feat/T-0001-...` matches a real finished task.
- The task-ID in a task branch name, not the full branch name, is the stable key to a task file:
  the type prefix and slug can differ from what `Task.branch` generates.
