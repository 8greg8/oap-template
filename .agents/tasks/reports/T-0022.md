## What was done

1. Re-checked the task against the plan and `develop`: no `CHANGELOG.md` or `changelog.d/` existed,
   `next_version.py` has `classify`, and the task and plan agree.
2. `scripts/changelog.py` loads the sibling `next_version.py` with `importlib` and calls its
   `classify`, so commit classification is the same code, not a copy. It loads lazily, on the
   first `check`.
   - `check <base> <tip>`: lists non-merge commits in the range, fails on a `feat`, `fix` or
     breaking commit when no commit in the range adds a fragment (per commit,
     `--diff-filter=A --no-renames`), and validates the entries of `changelog.d/` at `<tip>`,
     listed with `git ls-tree` and read with `git show`, never from the working tree.
   - `preview [<version>]`: headed `## [X.Y.Z] - <today>` with a version, `## [Unreleased]`
     without. Changes nothing and never runs `next_version.py`.
   - `assemble <version> [--date]`: accepts `X.Y.Z` or `vX.Y.Z`. Refuses (exit 1, nothing
     changed) on a non-empty `[Unreleased]`, any file failing the rules, no fragments, a missing
     heading and an existing version. Otherwise it writes the dated section in Keep a Changelog
     order, fragments by file name within a category, and deletes the folded fragments. It edits
     the working tree only and does not stage. It writes no compare-link footer.
   - Fragment rules: `<id>` is `[A-Za-z0-9][A-Za-z0-9_-]*`. Any file in `changelog.d/` other than
     `README.md` that is not `<id>.<category>.md` fails as a bad name, hidden files included. A
     bullet is a line starting `- ` or `* `, with indented continuation lines. A placeholder
     bullet has empty text or matches `\bto-?do\b`, `TBD`, `FIXME` or the literal `<...>`, all
     case-insensitive. A bullet naming `changelog.d/<id>.<category>.md` is valid.
   - Exit codes: `check` 0 pass, 1 missing or invalid fragment, 2 usage error or git cannot
     resolve `<base>` or `<tip>` or list the range. `assemble` and `preview` use 1 for a refusal
     and 2 for a malformed version or date.
3. Added `CHANGELOG.md` (Keep a Changelog 1.1.0 header, SemVer link, empty `## [Unreleased]`).
4. Added `changelog.d/README.md` (no template name), `changelog.d/template.added.md` (D6 summary)
   and `changelog.d/T-0022.added.md`.
5. `tests/test_changelog.py` (112 tests) runs the script as a subprocess in real temporary git
   repositories. It reads no file of this repository's `CHANGELOG.md` or `changelog.d/`.

## Known limitations

- `check` reads `<base>..<tip>` as given. Choosing the range (merge base, first push) is the
  pre-push hook's job (T-0023).
- Keep a Changelog footer link definitions (`[Unreleased]: ...`) are kept if present but never
  created or updated.
- `assemble` deletes fragments with a plain file delete, not `git rm`, and stages nothing. The
  release command (T-0024) stages the result.
- Only bullets are checked for placeholders. An unindented prose line outside a bullet is not
  checked and would be copied into the changelog.
- The placeholder matches `TBD` and `FIXME` anywhere in a bullet, including inside a longer word,
  as the amended text says "contains".

## Lessons learned

- Modules loaded with `importlib.util.spec_from_file_location` are not in `sys.modules` unless
  added by hand. A `@dataclass` under `from __future__ import annotations` then fails at import.
  Use `NamedTuple` in `scripts/` files that tests load this way.
- ruff's `DTZ011` bans `datetime.date.today()` here. Use
  `datetime.datetime.now().astimezone().date()`.
- `git log` detects renames by default. Add `--no-renames` when filtering on `--diff-filter=A`.
- A gate run before new files are tracked can miss scans that read `git ls-files`. Commit first,
  then run the gate.
- Re-read the task file on `develop` before a fix round; the worktree copy can be stale.
