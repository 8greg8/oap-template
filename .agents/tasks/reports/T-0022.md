## What was done

2. Wrote `scripts/changelog.py`. It loads the sibling `next_version.py` with `importlib` and calls
   its `classify`, so commit classification is the same code, not a copy.
   - `check <base> <tip>`: lists non-merge commits in the range (`git log --no-merges`), fails on a
     `feat`, `fix` or breaking commit when no commit in the range adds a fragment (per commit,
     `--diff-filter=A --no-renames`), and validates every fragment in the tree at `<tip>`.
   - `preview [version] [--date]`: prints the section and changes nothing. Without a version it
     asks `next_version.py --quiet`, and falls back to the label `Unreleased` when that finds
     nothing to release.
   - `assemble <version> [--date]`: refuses a non-empty `[Unreleased]`, an invalid fragment, no
     fragments, a missing heading and an existing version. Otherwise it writes the dated section
     in Keep a Changelog order, then deletes the folded fragments. Nothing is written on refusal.
   - Fragment rules: `<id>.<category>.md` with one of the six categories, at least one bullet,
     no placeholder words (the tokens in `PLACEHOLDER_RE`). `README.md` and
     hidden files are skipped everywhere; any other file in `changelog.d/` must be a valid fragment.
   - Exit codes: 0 success, 1 failed check or refusal, 2 usage or git error.

## Lessons learned

- Modules loaded with `importlib.util.spec_from_file_location` are not in `sys.modules` unless
  added by hand. A `@dataclass` under `from __future__ import annotations` then fails at import.
  Use `NamedTuple` in `scripts/` files that tests load this way.
- ruff's `DTZ011` bans `datetime.date.today()` here. Use
  `datetime.datetime.now().astimezone().date()`.
- `git log` detects renames by default. Add `--no-renames` when filtering on `--diff-filter=A`.
