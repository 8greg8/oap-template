## Known limitations

Open question for the owner: the real `autofix.sh` and `gate.sh` do not handle quote or non-ASCII names. `staged_files` in `scripts/lib/common.sh` runs `git diff --cached --name-only` without `-z`, so git quotes such paths (`"\304\215..."`). `ruff` then reports `No such file or directory`, autofix does nothing and the gate fails, which blocks the commit loudly. Spaces work end to end. The hook itself is correct for all names (proved with stub autofix and gate), but the full pipeline is not. The fix belongs in `scripts/lib/common.sh` and the two callers (a NUL-delimited read, or `-c core.quotePath=false`, which would not cover quotes). That is under `scripts/`, which is ask-first and a non-goal here, so it was not changed.

Also not proven: real execution under bash 3.2 (Docker daemon unavailable) and under non-GNU `xargs` (BSD `xargs -0` is expected to behave the same).

## Lessons learned

- A rename is invisible to a `--diff-filter=ACMR` listing as anything but its new path. Use `--no-renames` and no filter when deciding on "what did this commit touch", as `pre-push` does.
- `git add -- <name>` treats `[`, `*` and `?` in a name as pathspec globs, so a test that stages `a[1].py` must use `:(literal)a[1].py`, and the hook must set `GIT_LITERAL_PATHSPECS=1`.
- Hook tests with stub `autofix.sh`/`gate.sh` cannot show problems inside the real scripts. Check unusual names against the real `staged_files` too.
