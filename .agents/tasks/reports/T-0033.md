## Known limitations

- Deviation from the task text: `git ls-tree` fails with "pathspec magic not supported" for `:(exclude,glob)` (git 2.43.0). The key listing is `git ls-files -s -- . <excludes>` on a temporary index built with `git read-tree --index-output`. The matcher is still git's pathspec in all three places, and the key is a hash either way.
- The tool versions in the key come from the checkout where `gate.sh` runs. A temporary-worktree gate recomputes them there, so a commit with a different `.python-version` would write its record under another key and the outer lookup would miss it. `--if-needed` still exits 0 on a passed gate.
- The rule that `slow=yes` is never overwritten by `slow=no` is implemented but untested, since nothing writes `slow=no` until T-0034.
- The hook skip rule limits `git log` by pathspec; `--full-history` keeps side-branch commits visible, and the existing merge cases pass.
- Hook behavior changes: `.agents/` files outside `RECORD_PATHS` (process docs, templates, task tooling) run the gate. Tags trigger no gate (a tag-only push used to run the full gate; the existing hook test that expected a gate for tags was changed to match the amended task).
- The orchestrator's post-merge check is a process rule and is unchanged here (T-0036).

## Lessons learned

- `git ls-tree` accepts no pathspec magic in git 2.43; `git ls-files` does. A temporary index from `git read-tree --index-output=<file>` gives a pathspec-filtered listing of any commit without touching the real index.
- A bash-only `export -f` in a scratch `scripts/config/gate.sh` breaks `.husky/pre-push`, which sources the file under `sh`. Log from a stub command on `PATH` instead.
- `git log <range> -- <pathspec>` simplifies history; add `--full-history` when every commit of the range must count.
- Do not use `pkill -f` or `kill` by guessed pid in a shared container: other agents' runs match the pattern, and it can kill the calling shell.
