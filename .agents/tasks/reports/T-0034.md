# Report — T-0034: Mark the slow init tests and skip them for safe-list changes

## Summary

The two end-to-end init tests carry a `slow` marker. `scripts/gate.sh` skips them only when every path changed since the base is on `SLOW_SAFE_PATHS`. Other changes, `--all` and pushes to `main` run them. Records carry `slow=yes|no` and `--if-needed` honors it. All acceptance criteria are met.

## Known limitations

- Commits were made with signing on; the file-descriptor caveat did not occur, so no signing override was used.
- `--all` is passed to the inner `gate.sh` of a temporary worktree. A commit whose own `gate.sh` predates this change would reject the flag. Only a branch not rebased onto this change can hit it.
- The base for a named commit uses the checked-out branch to choose `develop` or `main` (hotfix rule), as the task states. The inner gate of a temporary worktree is detached and uses the `develop` base. The `--all` hand-off above keeps the slow tests whenever the outer check needs them.
- The pre-push skip rule is unchanged: a push to `main` that touches only `RECORD_PATHS` runs no gate at all, so it does not run the slow tests either. See open questions.
- The stale "fail-fast" sentence in DEV_TOOLING_SPEC.md § `scripts/gate.sh` (the gate counts failures and runs every gate) predates this task and is untouched.

## Lessons learned

- A scratch repo for slow-selection tests needs an `origin/develop` ref at the old tip, or the base is the local `develop` and a fast-forwarded branch has an empty change set (which runs the slow tests).
- `git ls-files --others` and `git diff --name-only` both accept the `:(exclude,glob)` pathspecs, so one pathspec list serves records, the hook and the slow-test safe list.
- A heredoc terminator such as EOF inside a Python heredoc ends the shell heredoc early; write scripts that contain shell heredocs to a file with a different delimiter.
