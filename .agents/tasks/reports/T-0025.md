## Open questions

1. The Scope says to remove fragments "matching" the name pattern. The Required behavior says
   `changelog.d/` holds only `README.md`. These differ only for a badly named file. I removed
   matching files only, the conservative choice, because a badly named file is not a fragment
   and deleting it silently would hide a mistake. Say if every file other than `README.md`

2. The dry run lists one `remove` line per fragment, as it does for task state, instead of one
   line for the directory. The task says "list both"; this reads as both changes.

## Lessons learned

- `tests/test_init_project.py` copies `git ls-files` into a scratch repo, so a new file must be
  tracked, that is committed, before the tests see it. Untracked fragments are invisible to the
  scratch copy.
- Compare the generated changelog with the template's text up to `## [Unreleased]`, not with the
  whole file. After the first release the template's file gains released sections.
- The scratch-copy tests run the real `scripts/changelog.py`, so the generated project is proven
  to parse, not only to match a string.
