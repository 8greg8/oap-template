## Known limitations

- The dogfood run on a real GitHub repository is `not run`.
- If a lock command fails (offline, or `--skip-install` in a clone without `node_modules/`, where `husky` is missing), step 3 prints the commands and continues, as the plan says. Step 8 then commits the stale `uv.lock` or `package-lock.json`, which still name the template. The user must run the printed commands and commit the result. The script does not warn again before the commit.

## Lessons learned

- `npm install --package-lock-only` still runs the root `prepare` script. In a copy without `node_modules/`, that is `husky: not found` and exit 127, which looks like a network failure. Run `npm ci` first.
- `husky` sets `core.hooksPath` in the repo where it runs, so a test copy that ran `npm ci` or `npm install` has live hooks from then on, whatever the test set earlier.
- A commit body line over 100 characters fails `scripts/commit_lint.py`; wrap bodies.
- When a later step makes an earlier step's test assumptions false (the script removes itself), keep the earlier cases by truncating `STEPS` in a small driver rather than editing their assertions.
