# Report — T-0037: Fix the generated README's per-commit gate advice

## Summary

The README that `init_project.py` generates told a reader to run the full gate before every commit.
Its `## Checks` section now advises `scripts/gate.sh --fast` while working and names the full gate as
what the independent verifier and the `develop`/`main` pushes run. All acceptance criteria are met
by the executor's own runs; the independent verify is still to come.

## What was done

- Re-checked `README_TEXT` in `init_project.py` against `develop` (c355a37) and `CONTRIBUTING.md`.
  The old text was as the task describes. One discrepancy: the task's Goal says the pre-push hook
  runs the full gate, but `CONTRIBUTING.md` § Git hooks says a task-branch push runs
  `gate.sh --fast` and only `develop` and `main` pushes run the full gate. The text follows
  `CONTRIBUTING.md` and the task's Scope, which names the verifier and the `develop`/`main` push
  checks as the full-gate runs.
- Wrote two tests first, with expected strings taken from the task and `CONTRIBUTING.md`. They
  failed on the old text.
- Rewrote the `## Checks` section: a `scripts/gate.sh --fast` block for work in progress, a line on
  the hooks, and the full `scripts/gate.sh` block with who runs it.
- Added `changelog.d/T-0037.added.md` in the "Before the first release" style.
- One mechanical test fix: the first run failed on the case of "while working" at a sentence
  start. The test now compares against `checks.lower()`. The expected string is unchanged.

## Lessons learned

- Create the report after the full gate finishes, or the untracked file makes the tree dirty and
  the run writes no gate record.
- `gitflow.sh <type> start` leaves the worktree without `.husky/_` when the primary checkout has no
  `node_modules`. Run `npm ci` in the worktree before the first commit.
