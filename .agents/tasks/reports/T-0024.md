## What was done

- `scripts/next_version.py`: while the last tag's major is 0, a breaking change bumps minor.
  Module docstring and `bump` docstring state the rule. The `git describe` lookup is unchanged.
- `scripts/release.py`, rewritten:
  - Dry run by default: prints the `next_version.py` report (version, commits) and the output of
    `changelog.py preview <version>`. Changes nothing.
  - `--yes`: from `develop`, checks out `main` and merges with `chore(merge): merge develop into
    main`; from `main` this step is skipped. Then `changelog.py assemble`, `git add -A --
    CHANGELOG.md changelog.d`, commit `chore(release): vX.Y.Z`, annotated tag on that commit,
    then `develop` is brought up to `main`: `--ff-only` when `git merge-base --is-ancestor
    develop main` holds, otherwise `--no-ff` with `chore(merge): merge main into develop`. The
    starting branch is checked out again.
  - `--version vX.Y.Z`: only that form is accepted (usage error, exit 2, otherwise). It must be
    higher by SemVer than the highest `vX.Y.Z` tag (`v0.0.0` when none).
  - `--push` (implies `--yes`): `git push --atomic origin main develop vX.Y.Z`. On rejection it
    prints that command as the retry and exits 1; the local release stays complete.
  - Refusals, all before any change: starting branch not `main`/`develop`; `git fetch origin`
    failing; dirty tree; local `main` or `develop` missing, or missing on `origin`, or behind,
    ahead or diverged; either branch checked out in another worktree; nothing to release;
    invalid or missing changelog fragments; tag already exists; `--version` not higher.
  - A failure after the first change (merge conflict, hook rejecting the release commit, failed
    tag or checkout) stops and prints the current state, the commands to finish by hand and the
    commands to undo. It never resets, forces or retries. Branch names come from
    `scripts/config/gate.sh`. The only network use is `git fetch origin` and `git push`.
- `scripts/gitflow.sh`: the hotfix finish message now says nothing is pushed or tagged yet, then
  `git push origin main develop`, then `git checkout main && scripts/release.py --yes`.
- Tests added: `tests/test_next_version.py` (27 cases), `tests/test_release.py` (37 cases), and one
  hotfix-message case in `tests/test_gitflow.py`.
- `changelog.d/T-0024.changed.md`: three bullets, the first starting with "Breaking:".
- The behavior commit is `feat(release)!:` with a `BREAKING CHANGE:` footer.

## Known limitations

- Open question, conservative choice: `--version` does not bypass "nothing to release". With no
  `feat`/`fix`/breaking commit, or no fragment, the release is refused even with `--version`. The
  plan lists "nothing to release" without exception and `changelog.py assemble` refuses to run
  without a fragment.
- Open question, conservative choice: started on `main` while `develop` holds unreleased work, the
  release uses only `main`'s commits and then back-merges `develop` with `--no-ff`. The plan does
  not list this case as a refusal and the plan's step 4 covers it.
- Addition beyond the plan's refusal list, for safety: refuse when the target tag already exists
  or when no fragment would be assembled, so a failure cannot occur after the first change.
- `git fetch origin` is plain: remote tags unreachable from fetched history are not fetched, so
  the "tag already exists" check sees only local tags.
- The dry run applies every refusal, including a dirty tree, as the previous script did.
- The mid-run failure paths tested are a merge conflict into `main` and a hook rejecting the
  release commit. The failures of the tag, the `develop` update and the final checkout share the
  same reporting code but have no dedicated test.
- The undo commands for a human include `git reset --hard` and `git branch -f`. The script only
  prints them.

## Lessons learned

- A refusal test cannot compare remote-tracking refs before and after, because the required
  `git fetch origin` legitimately updates them. Compare `refs/heads` and `refs/tags` only.
- `git branch -m` on the bare remote does not remove the stale `origin/<branch>` ref in the clone.
  A test of a missing remote branch must also delete the tracking ref.
- Commit before the final `scripts/gate.sh` so `tests/test_init_project.py` and the staged-file
  checks see tracked files; keep the gate result tied to the commit hash.
