## Known limitations

- `is_branch_merged` only treats a branch at exactly the `develop` tip as empty. If `develop` has advanced since an empty branch was cut, ancestry cannot tell it from a merged branch, so it is still reported until its first commit. Ancestry alone cannot separate the two cases.
- `gitflow.sh start` branches from local `develop` (after fetching `origin/develop`), as before, not from `origin/develop`. Unchanged for all kinds.
- The new kinds do not validate the topic format (`T-NNNN-<slug>`).
- Not run under real bash 3.2.

## Follow-up recommended

- If stale empty worktrees after `develop` advances matter, track branch creation (for example by reflog) in `housekeep.py`.

## Lessons learned

- `housekeep.py`'s old merged check was ancestry-only, so any test that wanted a "merged" worktree could pass with an empty branch. Such tests must commit on the branch and merge it.
- `ruff format` wraps lines at 88 columns here; the gate's format check fails on a single over-long condition, so run `uv run ruff format <files>` before the gate.
