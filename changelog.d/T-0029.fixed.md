- Breaking: `scripts/release.py --push` no longer implies `--yes`. Without `--yes` it exits 2
  with a usage message and changes nothing; use `--yes --push` to release and push.
- `release.py` prints both stdout and stderr, labelled, when a step fails, so a hook's
  diagnostics on stdout are no longer lost.
- When bringing `develop` up to `main` conflicts on a changelog fragment, the printed recovery
  steps now say to resolve it as deleted (`git rm <path>`), because `main` already folded it and
  keeping it would fold it twice at the next release.
- A rejected `--push` now names both likely causes: another push won the race, or a local
  pre-push hook failed.
- `release.py` now refuses a repository with no commits with a clear message and exit status 1
  instead of a traceback.
- The recovery commands no longer print `git checkout develop` twice when the run starts on
  `develop`.
